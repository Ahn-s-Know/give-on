### 1-2. 심사위원 선호 패턴 분석

2025년 수상작 10개를 관통하는 **공통 특징 5가지**:

1. **AI + 공공데이터 결합** — 거의 모든 수상작에 공통 적용
2. **취약계층 타겟팅** — 노인, 영유아, 폐질환자 등 구체적 대상 명시
3. **ESG 정량화** — 탄소절감량, 전력 생성량 등 수치를 직접 보여줌
4. **게임화/구독/보상 구조** — 지속적 참여를 유도하는 설계
5. **골든타임/긴급대응** — 즉각적이고 명확한 사회적 임팩트

> **2026년 추가 핵심 키워드:** 공모전 명칭이 **"기후부 AX(AI Transformation) 아이디어 경진대회"** 로 변경됨에 따라, **AI Agent를 활용한 자동화**가 단순 AI 분석보다 훨씬 유리한 평가 요소가 됨.

## 2. 세이프에어 × 에너지 알림 비서 결합 검토

### 2-1. 개별 수상작 심층 분석

#### 🔵 세이프에어 (SafeAir)

> 서울시 교통량·공사장·소각장에서 발생하는 국소 대기오염 정보를 실시간 수집·분석해, 취약계층에게 맞춤형 건강 조언과 오염 회피 경로를 안내하는 모바일 앱

**강점**

- 실외(Outdoor) 대기 데이터 활용이 정교함
- AI 예측 + 경로 안내라는 즉각적 UX
- AR을 활용한 시각적 임팩트

**약점 / 한계**

- **실내(Indoor) 환경 완전 미반영** — 취약계층은 외출보다 실내 체류 시간이 압도적으로 길음
- 앱을 능동적으로 켜야 하는 구조 → 디지털 취약계층 접근성 낮음
- 대기오염 정보 → 행동 안내까지만, **에너지·복지 연결 없음**

---

#### 🟠 기후 약자를 위한 주택 에너지 알림 비서 (힘벗)

> 폭염·한파에 취약한 노인, 에너지 취약계층을 위해 에너지바우처 사용과 관리를 돕는 에너지 돌봄 서비스

**강점**

- 에너지바우처라는 구체적 정책 직접 연계
- 실내 환경·에너지 소비에 집중한 설계
- 사회 임팩트 명확 (매년 폭염·한파 사망자 실재)

**약점 / 한계**

- **대기오염·실외 환경 데이터 미활용** — 미세먼지 나쁜 날 창문을 열면 에너지 낭비 + 건강 악화라는 복합 상황 미처리
- 에너지 소비 "알림"에 그침 → AI Agent로의 발전 여지 있음
- 바우처 잔액 관리 위주 → 사용자 동기 부여 약함

---

### 2-2. 결합의 타당성 — 연구 근거

**두 수상작은 사실 같은 사람을 다른 각도에서만 바라본 서비스입니다.**

연구에 따르면 독거노인 비율이 높을수록 폭염과 같은 이상기후에 취약하며, **대기오염 배출시설이 많이 설치된 지역일수록 사망률도 함께 증가**하는 것으로 분석되었습니다. 즉, 기후 취약계층은 대기오염 문제와 에너지 문제를 동시에 겪고 있습니다.

또한 고농도 대기오염이 관측된 후 **1~2일 이내에 심혈관계질환에 의한 취약계층 사망자 수가 크게 증가**한다는 보고도 있어, 두 데이터를 통합해 선제적으로 대응하는 것이 핵심입니다.

열악한 실내환경 역시 폭염·한파로 인한 건강 영향을 가중시킨다는 연구 결과는, 두 서비스를 **실내 환경 중심으로 통합**해야 한다는 강력한 근거가 됩니다.

| 구분 | 세이프에어 | 에너지 알림 비서 | **결합 시** |
|---|:---:|:---:|:---:|
| 다루는 공간 | 실외 | 실내 | **실내외 통합** |
| 다루는 위험 | 대기오염 | 에너지 부족 | **복합 위험** |
| 대상 | 외출 중인 취약계층 | 집 안의 취약계층 | **24시간 전방위** |
| AI 역할 | 경로 추천 | 잔액 알림 | **자율 의사결정** |

> **결론:** 결합하면 **"실내외 통합 기후건강 생존 플랫폼"** 이 됩니다.

## 3. 결합 아이디어 설계 — ClimaShelter

### 3-1. 프로젝트 개요

```
서비스명: ClimaShelter
부제:     기후 약자 통합 주거 안전 AI 에이전트
```

**한 줄 정의**

> 대기오염(실외) + 실내온도·에너지(실내)를 동시에 감지해, 취약계층이 언제 창문을 열고/닫고 에너지 바우처를 언제 어떻게 써야 하는지를 **AI Agent가 자동으로 판단·행동**해주는 서비스

---

### 3-2. 핵심 시나리오

#### 시나리오 A — 폭염 + 미세먼지 나쁨

```
상황: 실외 35°C, PM2.5 '나쁨' / 실내 32°C
```

| 기존 앱 | 대응 |
|---|---|
| 세이프에어 | "외출 자제" 알림만 발송 |
| 에너지 알림 비서 | 에어컨 틀면 바우처 소모된다고 알림만 발송 |

**ClimaShelter AI Agent 대응:**

1. 실외 대기 나쁨 감지 → **"창문 닫기"** 자동 권고
2. 실내 온도 32°C 초과 → 에어컨 가동 필요 자동 판단
3. 잔여 바우처 자동 조회 → 충분하면 즉시 가동 권고
4. 바우처 부족 → 추가 신청 가능 여부 자동 확인 + 신청 안내
5. 보호자 앱에 현재 상황 요약 자동 발송

---

#### 시나리오 B — 한파 + 대기 보통

```
상황: 실외 -10°C, PM2.5 '좋음' / 실내 14°C
```

**ClimaShelter AI Agent 대응:**

1. 실외 기온 낮으나 대기 좋음 → **"환기 15분 권고"**
2. 실내 온도 위험 수준 감지 → 난방 가동 즉시 권고
3. 동절기 바우처 최적 에너지원 자동 추천 (도시가스 vs 전기 → 잔액·효율 계산)
4. 한파특보 발령 시 → 지자체 담당자 자동 알림 발송

---

#### 시나리오 C — 평상시 예방적 관리

**ClimaShelter AI Agent (매일 오전 8시 자동 실행):**

1. 오늘의 외부 대기질 예보 + 기온 리포트 생성
2. 에너지바우처 잔액 D-30일 사전 경고 알림
3. 이번 달 에너지 소비 패턴 분석 → *"오늘 낮 12-2시 에어컨 효율 최고"*
4. 고위험일 예측 → 보호자에게 *"이번 주 목요일 폭염특보 예상, 확인 바랍니다"*

---

## 4. 공공데이터 연계 설계

총 **7개 이상의 공공데이터**를 교차 융합하는 구조로, 심사위원이 선호하는 "복수 데이터 융합 활용" 조건을 충족합니다.

| 데이터명 | 제공 기관 | 형태 | 활용 목적 |
|---|---|:---:|---|
| 실시간 대기오염 (PM2.5, O3, NO2) | 한국환경공단 에어코리아 | OpenAPI | 실외 공기질 실시간 감지 |
| 대기오염 예보 (주간) | 한국환경공단 | OpenAPI | 미래 위험일 사전 예측 |
| 동네예보 (기온·습도·풍속) | 기상청 | OpenAPI | 폭염·한파 위험도 산출 |
| 기상특보 (폭염·한파 경보) | 기상청 | OpenAPI | 즉각 위기 알림 트리거 |
| 생활기상지수 (체감온도, 폭염지수) | 기상청 | OpenAPI | 체감 위험도 정밀 산출 |
| 에너지바우처 발급·현황 | 한국에너지공단 | 파일/API | 대상자 식별, 잔액 참조 |
| 에너지원별 요금 정보 | 한국전력·도시가스사 | 공공데이터 | 최적 에너지원 자동 추천 |

### 데이터 융합 흐름

```
[기상청 동네예보 API]──┐
[기상청 기상특보 API]──┤
                       ├──▶ [AI Agent 위험도 스코어 엔진]──▶ 행동 결정
[에어코리아 실시간 API]┤         │
[에어코리아 예보 API]──┘         ▼
                         [에너지바우처 API]──▶ 복지 연계 행동
                         [에너지 요금 DB]───▶ 최적화 추천
```

### 5-2. 앱별 역할 정의

#### 취약계층 앱 (iOS, SwiftUI)

- 복잡한 탭 UI 없음 → 홈 화면에 **"오늘의 상태" 신호등 하나**
- 음성 TTS로 상황을 읽어줌 (`AVSpeechSynthesizer` 활용)
- 에어컨/난방 권고 시 → 원터치 확인 버튼
- 긴급 상황 → 보호자 및 119 즉시 연결 버튼

#### 보호자 앱 (iOS, SwiftUI)

- 피보호자의 현재 실내/실외 환경 상태 실시간 표시
- 위험 수준 변화 시 푸시 알림 수신
- 에너지바우처 잔액 및 사용 내역 확인
- 복지 서비스 신청 대리 진행

#### 복지사 / 지자체 대시보드 (Web)

- 담당 구역 내 고위험 대상자 지도 시각화
- 당일 위험 지수가 높은 가구 우선 방문 목록 자동 생성
- 바우처 소진 임박 가구 일괄 조회
- 지역별 주간 위험도 리포트 자동 생성

### 5-3. AI Agent 핵심 로직

```swift
struct ClimateRiskScore {
    let outdoorPM25: Double      // 에어코리아 API
    let outdoorTemp: Double      // 기상청 동네예보 API
    let heatwaveAlert: Bool      // 기상청 기상특보 API
    let heatIndex: Double        // 기상청 생활기상지수 API
    let indoorTemp: Double       // IoT 센서 or 사용자 입력
    let voucherBalance: Int      // 에너지바우처 API

    var riskLevel: RiskLevel {
        switch (outdoorPM25, outdoorTemp, indoorTemp, voucherBalance) {
        case let (pm, t, it, v) where pm > 75 && t > 33 && it > 30:
            return v > 50000 ? .highRiskActionable : .highRiskCritical
        case let (_, t, it, _) where t < -10 && it < 15:
            return .coldDangerZone
        default:
            return .normal
        }
    }
}

enum RiskLevel {
    case normal              // 정상 → 일반 안내
    case highRiskActionable  // 위험 + 바우처 있음 → 즉시 가동 권고
    case highRiskCritical    // 위험 + 바우처 부족 → 긴급 복지 연결
    case coldDangerZone      // 한파 위험 → 난방 + 따뜻한 옷 권고
}
```

## 6. 리스크 및 보완 방안

### ⚠️ 리스크 1 — 개인정보 민감성

에너지바우처 정보 + 주소 + 건강 관련 데이터가 결합되어 개인정보 보호 이슈 발생 가능

**보완책**

- 개인 식별 데이터는 앱 서버에 저장하지 않고, 읍면동 행정복지센터 코드만 입력받아 **익명화된 지역 통계**로 연동
- 바우처 잔액 조회는 사용자 명시적 동의 기반 OAuth 방식으로 처리
- 데이터 최소 수집 원칙 (Privacy by Design) 적용

---

### ⚠️ 리스크 2 — 독거노인의 디지털 접근성

스마트폰 앱 자체에 대한 접근성이 낮은 고령자 사용자층

**보완책**

- 보호자·복지사가 대신 등록 가능한 **"대리 설정 모드"** 제공
- **카카오톡 알림톡 연동**: 앱 없이도 문자 기반 알림 수신 가능
- 음성 안내 UX 기본 탑재, 글자 크기 자동 대형화

---

### ⚠️ 리스크 3 — 실내온도 측정 인프라 부재

IoT 센서 없이 실내 온도를 자동으로 알 수 없는 상황

**보완책**

- MVP 단계: 사용자가 현재 실내 온도를 **직접 입력**하는 방식으로 구현
- 1단계 확장: 저가형 블루투스 온습도 센서 연동 (SensorTag 등)
- 2단계 확장: 스마트홈 플랫폼(삼성 SmartThings, Apple HomeKit) 연동 계획 명시
