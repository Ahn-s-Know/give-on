## 1. 서비스 개요

### 한 줄 정의

> 기후변화로 인한 가축 폐사를 AI가 선제적으로 예측·경보하고, 피해 농가를 시민 기부와 연결해 지역화폐 리워드로 순환시키는 **기후 재난 대응 + 사회 연대 플랫폼**

### 서비스명 및 구성

| 구성 | 플랫폼 | 주 사용자 |
|---|---|---|
| **Give On Farm** | iOS / Android 앱 | 축산 농가 |
| **Give On Give** | 웹 (give-on.kr) | 일반 시민·기부자 |
| **Give On Admin** | PWA (반응형 웹) | 운영팀·지자체 담당자 |
| **Give On API** | Python FastAPI 백엔드 | 공통 서버 |

## 2. 문제 정의 — 왜 지금인가

### 2-1. 기후변화로 인한 축산 피해 현황

기후변화는 더 이상 미래의 이야기가 아닙니다. 매년 여름과 겨울, 전국 축산 농가는 이상기후와 싸우고 있습니다.

**2025년 피해 규모**
- 폭염으로 가축 **146만 마리** 폐사 신고 (2025년 7~8월)
- 가금류(닭·오리)가 전체 피해의 약 88% 차지
- 전북 단일 지역에서만 **16만 6,453마리** 폐사, 401개 농가 피해
- 2024년 가을 폭설로 경기도 축산 분야 피해액 **1,811억 원**

**반복되는 구조적 문제**
- 폭염·한파가 매년 반복되지만 농가는 "경보가 너무 늦게 온다"고 호소
- 기상청 특보는 광역 단위 → 읍면동 단위 세밀한 예보와 괴리
- 피해 발생 후 보험 청구까지 수주일 → 그 사이 경영 위기

**기후변화 전망**
- 2030년 이후 연평균 폭염일수 지금의 2~3배 예상 (기상청)
- "일시적 재해"가 아닌 **상시적 기후 재난**으로 구조가 바뀌는 중

### 2-2. 기존 대응의 한계

| 기존 대응 | 한계 |
|---|---|
| 기상청 폭염 특보 | 광역 단위, 농가별 맞춤 행동 지침 없음 |
| 농식품부 문자 알림 | 경보 발령 후 전파 — "이미 늦은" 경우 多 |
| 가축재해보험 | 사후 보상 → 폐사 자체를 막지 못함 |
| 지자체 지원 | 예산 집행까지 시간 소요, 긴급 현물 지원 어려움 |

### 2-3. 시민 연대의 부재

피해 소식은 뉴스로 접하지만, 일반 시민이 **즉각적으로 행동할 수 있는 창구**가 없습니다. 기부 의향은 있지만 어디에, 어떻게 해야 하는지 모르는 것이 현실입니다.

## 3. 솔루션 설계

### 3-1. 핵심 가치 제안

```
기후 위기 속에서 농가는 "골든 타임"이 필요합니다.
Give On는 위기 2~3시간 전에 농가에 경보를 보내고,
피해 발생 시 24시간 안에 시민과 농가를 연결합니다.
```

### 3-2. 서비스 흐름 전체

```
[기상청 API] ──→ [AI Agent 위험도 산출]
                          │
              ┌───────────┼───────────┐
              ↓           ↓           ↓
         [위험 없음]  [주의 단계]  [위험 단계]
              │           │           │
         정기 리포트   예방 안내   즉각 경보 + 대응 가이드
                                      │
                               [폐사 피해 발생]
                                      │
                          [Give On Give 자동 등록]
                                      │
                     ┌────────────────┼────────────────┐
                     ↓                ↓                ↓
               시민 기부           물품 배송         포인트 적립
                     │                │                │
               세액공제 영수증   현장 도착 확인   지역화폐 전환
```

### 3-3. Give On Farm (농가 앱)

**핵심 기능**

- 축사 위치 기반 **읍면동 단위 기상 예보** 실시간 표시
- 축종별(닭·돼지·한우·오리) **임계값 자동 비교** → 위험도 신호등
- 위험 단계 도달 시 **즉각 푸시 알림** + AI 맞춤 대응 가이드
- 대응 체크리스트 완료 시 **보험사 대응 이력 자동 기록**
- 피해 발생 시 **원터치 신고** → 기부 페이지 자동 생성
- 고령 농가를 위한 **카카오 알림톡 SMS 보조**

**위험도 기준 (룰 기반 엔진)**

| 축종 | 주의 | 위험 | 긴급 |
|---|---|---|---|
| 닭 (육계·산란계) | 30°C 이상 | 33°C 이상 | 36°C 이상 |
| 돼지 | 28°C + 습도 65% | 30°C + 습도 70% | 33°C 이상 |
| 한우·젖소 | -5°C 이하 | -10°C 이하 | -15°C 이하 |
| 오리 | 32°C 이상 | 35°C 이상 | 38°C 이상 |

### 3-4. Give On Give (시민 웹)

**핵심 기능**

- 실시간 피해 농가 지도 — "지금 이 지역 농가가 어렵습니다"
- 필요 물품 목록 기부 (냉방팬·사료·방역용품 등)
- 카카오페이·네이버페이 원클릭 결제
- 기부 후 **즉시 세액공제 영수증** 발행 (연 5만원 이하)
- 지역화폐 포인트 적립 (기부액의 일정 비율, 지역별 연동)
- SNS 공유 — "내가 이 농가를 도왔어요"

**리워드 설계**

```
기부 1만원 → 세액공제 1,500원 (15%) + 지역화폐 500포인트
기부 5만원 → 세액공제 7,500원 + 지역화폐 2,500포인트
              = 기부했는데 실질 부담 41,000원
```

### 3-5. Give On Admin (관리자 PWA)

**핵심 기능**

- 전국/지역별 위험 농가 지도 실시간 시각화
- 위험도별 농가 우선순위 리스트 (현장 순회용)
- 기부 물품 매칭·배송 현황 관리
- 주간·월간 피해 통계 자동 리포트 생성
- 지자체 담당자 공유 링크 (앱 설치 없이 접근 가능)

## 4. AI Agent 구조

### 4-1. 전체 AI 설계 원칙

```
규칙으로 판단할 수 있는 것 → 룰 기반 엔진 (빠르고 저렴)
사람의 언어가 필요한 것   → Claude API (맞춤·자연스러움)
```

### 4-2. Claude API 활용 포인트

**① 위험 경보 메시지 생성**

단순한 "폭염 경보" 알림이 아니라, 해당 농가의 축종·사육 규모·지역 날씨를 반영한 맞춤 메시지를 생성합니다.

```
[룰 엔진] 닭 33°C 초과 감지
     ↓
[Claude API 호출]
입력: 농가정보(닭 5만 수, 경기 포천), 현재기온(34°C), 예측(내일 37°C)
출력: "포천 지역 현재 34°C, 내일 37°C 예보입니다.
       산란계 5만 수 기준 지금 즉시 환풍기 최대 가동,
       음수 온도 20°C 이하 유지가 필요합니다.
       오늘 오후 2-4시가 가장 위험한 시간대입니다."
```

**② 피해 농가 스토리 자동 생성 (기부 페이지용)**

농가가 피해를 신고하면, 입력된 정보를 바탕으로 기부 페이지 스토리를 자동 작성합니다.

```
[농가 신고 데이터]
위치: 전북 정읍, 닭 4만4천 수, 폐사율 60%, 피해액 약 2억원

[Claude API 생성]
"7월 폭염으로 30년간 키워온 닭 2만 6천 마리를 잃었습니다.
 정읍에서 3대째 이어온 농장인데 이번 여름이 가장 힘드네요..."
```

**③ 기부자 챗봇 응답**

기부 웹에서 시민의 질문에 자연스럽게 답변합니다.

- "기부하면 실제로 어디에 쓰여요?"
- "세액공제는 어떻게 받나요?"
- "지역화폐 포인트는 언제 들어오나요?"

### 4-3. AI Agent 실행 주기

| 타이밍 | 작업 | 사용 기술 |
|---|---|---|
| 30분마다 | 기상 데이터 수집 | APScheduler + 기상청 API |
| 즉시 | 임계값 초과 시 위험도 판단 | 룰 엔진 (Python) |
| 위험 감지 시 | 맞춤 경보 메시지 생성 | Claude API (claude-haiku-4-5) |
| 위험 감지 시 | FCM 푸시 알림 발송 | Firebase Cloud Messaging |
| 피해 신고 시 | 기부 페이지 스토리 생성 | Claude API (claude-haiku-4-5) |
| 매일 07:00 | 오늘 위험 예보 요약 발송 | Claude API + FCM |
| 매주 월요일 | 주간 통계 리포트 생성 | Claude API + PDF 생성 |

## 5. 공공데이터 활용 계획

Give On는 총 **6개 공공데이터 API**를 교차 활용합니다.

| # | 데이터명 | 제공 기관 | 형태 | 활용 목적 |
|---|---|---|---|---|
| 1 | 동네예보 조회서비스 | 기상청 | OpenAPI | 읍면동 단위 기온·습도 예보 |
| 2 | 기상특보 조회서비스 | 기상청 | OpenAPI | 폭염·한파 특보 즉각 트리거 |
| 3 | 생활기상지수 조회서비스 | 기상청 | OpenAPI | 체감온도·폭염지수 산출 |
| 4 | 축산농가 현황 | 농림축산식품부 | 파일 | 전국 농가 DB 구축 |
| 5 | 에어코리아 대기오염정보 | 한국환경공단 | OpenAPI | 대기질 복합 위험도 가산 |
| 6 | 지역별 지역화폐 정보 | 각 지자체 | OpenAPI/파일 | 기부 리워드 포인트 연동 |

### 데이터 융합 방식

```
기상청 동네예보 (기온·습도)
        +
기상청 생활기상지수 (폭염지수)
        +
에어코리아 (대기질)
        ↓
축종별 복합 위험 스코어 산출
(기온 단독보다 습도·대기질 결합 시 폐사율 더 정확히 예측)
```

```
설정 화면
```

```
메인 페이지

│   └── [기부하기 버튼]
├── [전국 피해 현황 지도]
├── [최근 기부 스트림] "서울 강남구 시민이 5,000원을 기부했습니다"
└── [내 기부 내역 / 리워드 확인]

기부 페이지
├── 농가 스토리 (AI 자동 생성)
```

```
대시보드
├── [요약 수치] 오늘 위험 농가 23곳 / 주의 47곳 / 기부 진행 중 5건

│   └── 농가명 / 위치 / 축종 / 위험도 / 전화번호
├── [기부 매칭 현황] 기부 완료 / 배송 준비 / 배송 중 / 도착 확인
└── [주간 통계] 총 알림 발송 수 / 피해 예방 추정 두수 / 기부 총액
```

## 7. 비즈니스 모델 및 수익 구조

Give On는 **민간 스타트업이 공공데이터를 활용해** 운영하는 서비스입니다. 정부는 데이터와 정책 연계를 제공하고, 수익은 민간이 창출합니다.

### 수익 Track 1 — 농가 구독료 (핵심 수익)

```
전국 축산 농가 약 90,000호 대상

Basic  월 30,000원 — 기상 경보 + 앱 알림
Pro    월 80,000원 — + AI 대응 가이드 + 보험 이력 자동 기록
Enterprise 협의   — 농협·생산자단체 단체 계약

침투율 3% 가정 시:
90,000 × 3% × 30,000원 = 월 8.1억 (연 97억)
```

### 수익 Track 2 — 기부 플랫폼 수수료

```
기부 중개 수수료 5~7%
기업 ESG 기부 연계 (대기업 → 농가 지원 ESG 활동)

연간 기부 총액 목표 10억 기준 → 수수료 5,000~7,000만원
```

### 수익 Track 3 — 보험사·지자체 B2G

```
농업재해보험사: 조기 경보 → 폐사율 감소 → 보험금 절감
→ 데이터 제휴 수수료 협약

지자체: 현장 순회 관리자용 Admin PWA 구독
→ 지자체 예산 집행 (공공 SaaS 조달 연계)
```

### 정부가 하지 않고 우리가 하는 이유

- 공공기관이 구독료를 받으면 민간 시장 침해 → 법적 문제
- 공모전의 목적 자체가 **민간 창업·사업화 연결** (수상 후 창업 공간·사업화 연계 지원)
- 공공데이터 개방 → 민간 혁신 → 시장 창출이 기후부가 원하는 그림

**지역 공동체 복원**

도시 시민과 농촌 농가를 연결하는 새로운 연대 구조. 지역화폐 순환으로 지역 경제 활성화.

**AX(AI 전환) 모범 사례**

공공데이터 + AI Agent로 기존 재난 대응 시스템의 골든 타임 문제를 해결하는 **환경 산업 AX 실증 모델**.
